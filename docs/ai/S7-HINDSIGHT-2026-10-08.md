# S7 delivery hindsight — 9 October 2026

## Finding

S7 activated on 20 September. Its first “Deliver Snapshot 7” promotion came 10 days, 10 hours, 33 minutes later, but failed the required matrix/artifact workflow. On 9 October it remains unreleased, over 18 days after activation. These are wall-clock intervals, not measured work hours; the record cannot prove a two-day counterfactual. Real gameplay defects combined with avoidable candidate, setup, qualification, and handoff churn.

## What consumed the time

- **Candidate churn and weak critical-path control.** At `9a2a0b6`, history showed 41 `MC-AI-0038` commits on `ai-dev` and 15 promotions to `ai-main`, without a release. These are churn counts, not labor hours. A promotion used an older source parent, invalidating its hosted evidence for newer `ai-dev`. Repeated six-hour estimates had no frozen candidate or measured remaining-gate schedule.
- **Local setup discovery was late.** The clean worktree lacked build configuration and had missing/mismatched vcpkg, private-prefix, Vulkan/CMake, and executable paths. The shared vcpkg root failed with `Operation not permitted` (no lock owner was established); a reused CMake cache still pointed there. Available private packages mismatched the lock (CoreCpp `8e1d6336…` / CoreProject `10200a38…`, required `d5759fa4…` / `a4d3fa8a…`). A pinned local prefix fixed configuration. vcpkg restored 16 packages; MPFR took 2.9 minutes and the default cache write failed. This explains friction, not the multi-day interval.
- **The playtest handoff was not proved.** The user's terminal showed a host start followed by client exit: `client launch syntax is '\<mode> [--address IP:PORT]'`; other attempts opened two windows. I should have checked arguments, process/window count, and visible gameplay before claiming readiness. Movement, collision, camera, and freeze defects were real. On 9 October, capture tests exposed TCP probes for ENet's UDP ports; MC-AI-0389 fixed three launch fixtures, MC-AI-0390 fixes four capture fixtures.
- **Platform contracts surfaced after promotion.** Android HWASan ran on Linux ARM and selected an incompatible tool (`adb: Exec format error`); hosted macOS emulator startup failed with `HVF error: HV_UNSUPPORTED`. Windows path/CRLF assumptions and an analyzer probe also failed late. No exact-candidate HWASan receipt or runner exists. Windows Release failed on the old ENet fixtures; the fix has only `ai-dev` fast-check evidence, not a full Windows rerun.
- **CI and local gates did not fail fast.** I waited on Android after a required Mac row failed. MC-AI-0388's hook recorded `index-match` failure but still ran Python for 85.88s; staging only the exact files then passed in 93.57s. A Stop-guard fix passes 9/9 tests but validates handoff receipts, not continued execution. One earlier claim that `s7-exec.zsh` was repaired was unsupported; it exists neither in the repository nor `/private/tmp` and that claim is withdrawn.
- **Performance misses remained diagnostic.** Full-game x200 measured 86 uncapped iterations/s at 15.277 ms p99.8; ordinary, border, and permission/collision runs measured 97, 29, and 85/s. No run met 200/s or established physical 120 Hz cadence. HUD FPS across different distances is not comparable, and none of this proves the target.

The successful Release capture used task-local pinned dependencies/build/cache and explicit Ninja/Vulkan paths. `mc_main` built all 60 steps; `PlayerPlaytestCaptureTest` passed 1/1 and its Python suite 4/4 in 265.198s. It captured four distinct full-load 2560×1440 scenes and swept 16 headings. Log and PNG hashes are in [version history](<../version_history/EarlyDev 0.1/EarlyDev 0.1.0 Initiation.md>) and [raw capture evidence](evidence/MC-AI-0390-capture-2026-10-09.raw.log). This closes screenshots only. Current refs are `ai-dev=4a56ef5c…` and `ai-main=42963be7…`; Snapshot 6 remains latest. S7 lacks exact promotion/matrix, artifacts, published-byte runtime, and Windows acceptance. Standard desktop CI disables renderer capture, so its Release pass is not screenshot evidence.

## Changes that would have shortened the path

1. Before the first release candidate, run a cheap preflight that prints checkout/tree, preset, dependency lock/package revisions, executable paths, renderer/emulator capability, expected process count, and exact launch command. Fail before builds on missing or mismatched inputs; use one task-local build/dependency/cache root and never reuse a CMake cache across identities.
2. Keep one immutable candidate per correction batch. Finish code, tests, screenshots, metadata, and review on `ai-dev`, promote that exact tree, and invalidate only evidence whose inputs changed.
3. Exercise Windows Release and Android lifecycle/HWASan provisioning before promotion. Keep each matrix row tied to workflow/run/SHA, stop waiting when a required sibling fails, and expose queued, skipped, failed, and passed separately.
4. Make the macOS capture suite a visible required acceptance job, not an opt-in local-only test. Keep a one-server/one-client playtest gate that proves syntax, one process, visible window, and sustained gameplay before handoff.
5. Gate performance claims on the same full-game workload, distance, x200 modifier, and raw timing samples; treat misses as blockers or explicit diagnostic-only results, never infer display cadence from HUD FPS.
6. Preserve the continuing-work contract: emit honest liveness, resume from the last verified state, and stop only on actual completion or a concrete external blocker. Keep the receipt guard, but do not mistake it for an execution-continuation mechanism.

The main failure was not that S7 lacked direction; it was that implementation and release qualification were treated as a sequence of loosely related attempts instead of one evidence-bound candidate. The fixes above address that process without relaxing any product or platform requirement.
