# S7 delivery hindsight — 8 October 2026

## Finding

S7 is still unreleased after ten calendar days. The delay came from moving candidates through implementation, playtest, platform checks, and publication without first establishing one reproducible release candidate. Real bugs required fixes, but setup retries, late platform discovery, stale promotions, slow failure detection, and premature handoffs added avoidable time. Available records do not measure active work hours, so they cannot prove that a two-day finish was achievable.

## Why it took so long

- **Candidate churn:** At `9a2a0b6`, history showed 41 `MC-AI-0038` commits on `ai-dev` and 15 first-parent `ai-main` promotions without a release. These are churn counts, not hours. One promotion used an older source parent and invalidated its hosted evidence; repeated six-hour estimates had no measured critical path.
- **Local setup:** The fresh worktree lacked a Debug build and key variables (`VCPKG_ROOT`, `VCPKG_INSTALLED_DIR`, private dependency prefix, Vulkan SDK, CMake prefix) were absent or inconsistent. A reused cache mismatched source locks; matching pins made the integration gate pass. Restricted execution denied process inspection; a central capture then stalled at Launch Services/XPC with its client idle at 0% CPU for about six minutes. The same host-context capture passed in 16.339 seconds. A Launch Services repair registered no apps and did not remove this execution-context boundary.
- **Playtest path:** The user's transcript showed the host start then client exit with `client launch syntax is '\<mode> [--address IP:PORT]'`; multiple windows appeared on other attempts. I should have verified arguments, process count, and visible window before handoff. Movement, collision, camera, and freeze defects were real and required corrections.
- **Platform qualification:** Android HWASan first ran on Linux ARM and selected an incompatible SDK archive (`adb`: `Exec format error`); hosted macOS then failed emulator startup with `HVF error: HV_UNSUPPORTED`. Windows path/CRLF/host assumptions and an unsupported analyzer probe also surfaced late. The corrected workflow requests only a unique candidate/run label; registration must be ephemeral with `--no-default-labels`. The 105 focused workflow/SDK tests pass, but there is no registered runner or exact-candidate HWASan pass. The latest read-only GitHub check found no registered runners; run 37782081739 failed and matrix run 37782081670 was cancelled.
- **CI and stopping:** I waited on queued Android work after a required Mac row had failed, and aggregate waits obscured terminal job state. The MC-AI-0388 hook failed `index-match` but still ran the full Python suite for 85.88s: `ai_check.py` records the preflight failure and continues all phases. Stashing six parent files let the exact staged retry pass in 93.57s. Move this preflight before expensive checks and test that later phases do not run after it fails. Separately, the local Codex Stop guard at `/Users/core-just/.codex/hooks/task_completion_guard.py` now checks retries; `/usr/bin/python3 /Users/core-just/.codex/hooks/tests/test_task_completion_guard.py` passed 9/9. This enforces receipt validation, not continued model execution.
- **Performance:** The existing full-game diagnostic measured x200 at 86 uncapped loop iterations/s with 15.277 ms p99.8; ordinary, wrapped-border, and permission/collision runs measured 97, 29, and 85 iterations/s. No measured run met the 200/s target or established physical 120 Hz display cadence. Screenshot HUD values are not comparable: central distance 72 showed 120.2 FPS, while full-radius scenes showed 33.9–45.1 FPS. The diagnostic miss was recorded; it must not be presented as a performance pass.

One earlier report claimed `s7-exec.zsh` had been made fail-fast. No such file exists in this repository or at `/private/tmp/s7-exec.zsh`; that claim was unsupported and is withdrawn.

## Prevention

1. Before expensive checks, fail-fast on exact checkout/tree, staged scope, parent SHA, preset, dependency locks/package identity, required variables, process-inspection permission, and renderer/emulator capability. Print the failed precondition.
2. Freeze one candidate per correction batch. Finish code, tests, screenshots, metadata, and review on `ai-dev`, then promote that exact source/tree. Any changed input invalidates its receipts.
3. Run platform smoke tests early: one server plus one client, valid CLI arguments, visible Mac window, native Windows tests, and Android lifecycle/HVF. Retain command, log, process IDs, and expected window count with the handoff.
4. Track each required CI job by workflow ID and exact SHA. Show passed/failed/queued/skipped separately; stop waiting when a required sibling fails. Preserve logs before cancelling obsolete work.
5. Keep sanitizer, analyzer, artifact, and runtime gates fail-closed. Register a candidate-specific HWASan runner only with separate authorization, ephemeral mode, and no default labels. Never substitute a local-only result for the exact hosted receipt.
6. Keep S7 active until promotion, strict/tag checks, all 13 rows, packages/sidecars and integrity, published Mac/Android runtime, and Windows acceptance are reconciled. Reuse checks only when a checker proves identical inputs.
7. The Stop hook now validates every retry. Continue while safe work remains; stop only with an evidence-backed completion receipt or a concrete external blocker.
