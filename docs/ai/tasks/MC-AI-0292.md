The Android manifest uses the default standard activity launch mode, so concurrent launches are not guaranteed to coalesce. The guard must serialize independent host processes and recheck state after acquiring the lock. |
| Acceptance | Concurrent invocations for the documented S7 AVD serialize across host processes. After lock acquisition each invocation revalidates the exact AVD/framework, scans connected devices for existing game clients, and checks the existing activity before deciding whether to start. Under a controlled simultaneous-start regression exactly one am start occurs; the other invocation reuses or foregrounds the same NativeActivity, or fails with a bounded actionable timeout. The OS releases the lock when a process exits, so stale lock files do not block later playtests. Existing wrong-AVD, unavailable-device, duplicate-client, and foreground-verification behavior remains unchanged. |
