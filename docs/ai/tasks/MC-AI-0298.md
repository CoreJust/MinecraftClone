## Code changes

- AndroidPlayerClient turns PreviewResidency change batches into position-driven, time/count-bounded tile mesh work, publishing shared LOD meshes and transactional seam bridges while pruning out-of-interest tiles.
- Android renderer uses the negotiated server distance as camera far plane and preserves tile mesh work across window recreation while clearing stale state on connection reset.
- Added PreviewMeshWorkQueue regressions for normalized neighbor propagation, deduplication, completed-key requeue, filtering, and interest pruning.
- Replaced Android's full render-distance tile-interest set construction and per-frame retention membership with exact wrap-aware tile membership and incremental movement deltas, avoiding a large synchronous cold-start allocation and traversal.
- Deferred Android PreviewResidency change draining until player interest is initialized and added a deterministic regression that verifies early changes remain pending and become mesh work once interest is ready.

## Resolution

- Changes: Android drains resident height-tile changes into a bounded deduplicated mesh queue, applies shared projected-area LOD and seam-aware publication, updates camera far plane from server render distance, and rebuilds/removes renderer meshes across interest and lifecycle changes. Android interest membership is an exact wrap-aware disk predicate rather than materializing the full render-distance disk on the render thread; movement uses incremental interest deltas. Residency changes are retained until player interest exists, preventing early terrain packets from being discarded before the first local-player position.
